Oracle 19c. 모든 식별자 영문, `VARCHAR2(N CHAR)` 단위 강제(한글 안전). 본 문서는 Phase 1 진행과 함께 갱신된다.

| 테이블 | 정의 위치 | 용도 |
|---|---|---|
| DEPARTMENTS | `backend/src/orgCustomerSchema.js` | 부서 트리(자기참조) |
| USERS | `backend/src/orgCustomerSchema.js` | 사용자(엔지니어/관리자) |

## Phase 1에서 추가될 테이블 (계획)

### 일정관리
- `EVENTS` — 일정(routine/tech/incident/meeting/install)
- `EVENT_PARTICIPANTS` — 참석자
- `ATTENDANCE_NOTICES` — 직출/직퇴 알림(현 attendanceMock.js의 Oracle화)

### 지원이력
- `SUPPORT_HISTORIES` — 'H-XXXXXX' ID, CLOB 다수
- `SUPPORT_HISTORY_PARTICIPANTS` — IS_MANAGER 플래그

### 지식베이스
- `KB_CATEGORIES` — 자기참조 트리
- `KB_DOCUMENTS` — 문서(인덱싱 진행률 컬럼 포함)
- `KB_DOCUMENT_TAGS`
- `KB_DOCUMENT_VERSIONS`

### 주간업무보고
- `WEEKLY_REPORTS` — PAYLOAD CLOB(JSON 직렬화)
- `WEEKLY_REPORT_ITEMS` — EVENT_ID/HISTORY_ID 연결
- `TEAMS` — DEPARTMENTS와 분리/통합 결정 후 확정

### 작업현황표
- `ROUTINE_PLANS` — 정기점검 계획(연/반기 단위)
- `ROUTINE_PLAN_CELLS` — 12개월 셀(pending/done/urgent)

### 조직도(추가)
- `POSITIONS` — 직급 마스터(현 USERS.POSITION_NAME 자유입력 마스터화 결정 후)

### 고객사(추가)
- `CUSTOMER_ASSIGNMENTS` — 고객사 ↔ 사용자(primary/secondary/sales)

### 관리설정
- `SERVICE_MASTER`, `SERVICE_MASTER_VERSIONS` — 서비스 마스터
- `CHECKLISTS` — 점검 체크리스트(PAYLOAD CLOB)
- `AI_PROVIDERS`, `AI_MODELS`, `AI_USE_CASES` — AI 모델 카탈로그
- `RBAC_ROLES`, `RBAC_PERMISSIONS`, `RBAC_ROLE_PERMISSIONS` — 권한 매트릭스
- `AUDIT_LOG` — 변경 감사 로그

## 명명 규칙

- 테이블/컬럼: 대문자 SNAKE_CASE
- PK: `<TABLE>_ID` 또는 도메인이 자연스러우면 외부 ID 그대로(USER_ID)
- IDENTITY: `NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY` (Oracle 12c+)
- 외부 시스템과 매칭되는 ID는 IDENTITY 미사용 (USERS.USER_ID처럼 NUMBER NOT NULL + 입력)
- 문자열: `VARCHAR2(N CHAR)` — BYTE 단위 금지(한글 잘림)
- CLOB: 큰 본문(WORK_DETAIL, PAYLOAD 등). 조회 시 `clobFetchHandler` 필수
- 시각: `TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL` — KST/UTC ADR 결정 후 통일
- 활성 플래그: `ENABLED NUMBER(1) DEFAULT 1 NOT NULL` (소프트 삭제)
- 외래키: `CONSTRAINT FK_<TBL>_<TARGET> FOREIGN KEY ...`
- 자식 테이블 삭제 정책: 명백한 부속(태그, 참여자)은 `ON DELETE CASCADE`. 그 외는 미지정 + 소프트 삭제

## 트랜잭션 단위

- 부모-자식 동시 INSERT/UPDATE는 한 트랜잭션 안에서 처리
- 트랜잭션 헬퍼: `infra/oracle/withTransaction.js` (rollback 자동)

## 인덱스 전략

| 패턴 | 인덱스 |
|---|---|
| FK 컬럼 | 자동 인덱스 권장(Oracle은 PK만 자동 생성) |
| 검색 조건 자주 쓰는 컬럼 | 단일/복합 인덱스 |
| 한글 정렬 | 클라이언트 `localeCompare(a, b, 'ko')` 우선 — DB NLS_SORT는 풀 스캔 위험 |

## Migration 정책

- 신규 컬럼: `MIGRATION_DDL` 배열에 추가, ORA-01430(이미 존재) try/catch로 무시
- 컬럼 제거: 다음 릴리스에서 `ALTER TABLE ... DROP COLUMN ...` 추가
