# ADR 0003 — 메뉴 단위 수직 완성(Vertical Slice)

## 상태
Accepted

## 컨텍스트

9개 메뉴 중 일부만 Oracle DB 연동 상태이고 나머지는 mockData/window 글로벌 의존이다. 전체를 현행화할 때 진행 단위를 어떻게 잡을지 검토했다.

후보:
- (a) 메뉴 단위 수직 완성 — 한 메뉴씩 DDL → API → UI → 문서까지 끝내고 다음
- (b) 작업 종류 단위 수평 — 전체 DDL 일괄 → 전체 API → 전체 UI
- (c) 공통 기반 후 메뉴별 수직

## 결정

**(c) Phase 0(공통 기반) 후 Phase 1(메뉴별 수직 완성).**

- Phase 0: 디렉토리 골격, 공통 유틸 추출, API envelope 표준, Pages.jsx 분해, docs 골격
- Phase 1: 9개 메뉴 각각 7-task(DDL → Repository → Routes → API 클라이언트 → UI 연결 → 기술서 → E2E)

## 결과

- 장점:
  - 공통 기반이 먼저라 메뉴 작업 중 패턴이 어긋날 위험 최소화
  - 메뉴 수직 완성 = end-to-end 검증이 매번 가능
  - 의존도 기반 순서(고객사 → 조직도 → 일정 → ...)로 진행해 외래키 무결성 자연스럽게 확보
- 단점:
  - Phase 0 자체가 공수가 큼 — 그러나 그 후 메뉴 작업이 빨라짐

## 메뉴 진행 순서

1. 1.8 고객사 (이미 동작 — 패턴 표준화)
2. 1.7 조직도 (이미 동작 — 패턴 표준화)
3. 1.9(일부) 관리설정 마스터/RBAC (다른 메뉴가 의존)
4. 1.2 일정관리
5. 1.3 지원이력
6. 1.4 지식베이스
7. 1.6 작업현황표 (지원이력 의존)
8. 1.5 주간업무보고 (일정/지원이력 의존)
9. 1.9(나머지) 관리설정 UI 분리
10. 1.1 홈 (모든 메뉴 데이터 의존 — 마지막)
