# 고객사 통합 관리 (Customers)

`nav='cust'` — 고객사 마스터, 별칭(검색용), 담당자 배정.

## 1. 메뉴 개요

- 사용자: 매니저(편집), 모든 사용자(조회)
- 책임: 고객사 CRUD, 별칭 다중 관리, 담당자 매핑(primary/secondary/sales)
- **이미 DB 연동 완료(고객사+별칭)** — Phase 1에서는 표준화 + 담당자 매핑 추가

## 2. 화면/UX 흐름

1. 진입 → 고객사 목록(검색, 필터)
2. "Add" → 고객사명 + 별칭 다중 입력 + 담당자 배정 모달
3. 행 클릭 → 편집 / 비활성화
4. 별칭은 검색 보조용 — `LOWER(NAME) LIKE :q OR LOWER(ALIAS) LIKE :q` 결합

## 3. 데이터 모델

기존 테이블(`backend/src/orgCustomerSchema.js`):

```sql
CUSTOMERS (
  CUSTOMER_ID NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY,
  CUSTOMER_NAME VARCHAR2(300 CHAR) NOT NULL,
  ENABLED NUMBER(1) DEFAULT 1 NOT NULL,
  CREATED_AT TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL,
  UPDATED_AT TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL,
  CONSTRAINT PK_CUSTOMERS PRIMARY KEY (CUSTOMER_ID)
)

CUSTOMER_ALIASES (
  ALIAS_ID NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY,
  CUSTOMER_ID NUMBER NOT NULL,
  ALIAS VARCHAR2(300 CHAR) NOT NULL,
  CONSTRAINT PK_CUSTOMER_ALIASES PRIMARY KEY (ALIAS_ID),
  CONSTRAINT FK_CA_CUSTOMER FOREIGN KEY (CUSTOMER_ID) REFERENCES CUSTOMERS(CUSTOMER_ID)
)
```

신규:
```sql
CUSTOMER_ASSIGNMENTS (
  ASSIGNMENT_ID NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY,
  CUSTOMER_ID NUMBER NOT NULL,
  USER_ID NUMBER NOT NULL,
  ROLE VARCHAR2(40 CHAR),                           -- primary | secondary | sales
  ENABLED NUMBER(1) DEFAULT 1 NOT NULL,
  CREATED_AT TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL,
  CONSTRAINT PK_CUSTOMER_ASSIGNMENTS PRIMARY KEY (ASSIGNMENT_ID),
  CONSTRAINT FK_CASN_CUSTOMER FOREIGN KEY (CUSTOMER_ID) REFERENCES CUSTOMERS(CUSTOMER_ID),
  CONSTRAINT FK_CASN_USER FOREIGN KEY (USER_ID) REFERENCES USERS(USER_ID),
  CONSTRAINT UK_CASN UNIQUE (CUSTOMER_ID, USER_ID, ROLE)
)
```

## 4. API 엔드포인트

| 메서드 | 경로 | 비고 |
|---|---|---|
| GET | `/api/customers?q=` | 별칭 포함 검색 |
| GET | `/api/customers/:id` | 상세(별칭 + 담당자 포함) |
| POST | `/api/customers` | 고객사 + 별칭 동시 등록(트랜잭션) |
| PATCH | `/api/customers/:id` | 수정 |
| DELETE | `/api/customers/:id` | 비활성화 |
| GET | `/api/customers/:id/aliases` | 별칭 목록 |
| POST | `/api/customers/:id/aliases` | 별칭 추가 |
| DELETE | `/api/customers/:customerId/aliases/:aliasId` | 별칭 삭제 |
| GET | `/api/customers/:id/assignments` | 담당자 목록 |
| POST | `/api/customers/:id/assignments` | 담당자 추가 |
| DELETE | `/api/customers/:customerId/assignments/:assignmentId` | 담당자 제거 |

## 6. 주요 비즈니스 로직

- **고객사 + 별칭 동시 등록**: `withTransaction`으로 INSERT CUSTOMERS → INSERT CUSTOMER_ALIASES N건 → commit
- **검색**: 메인 NAME과 별칭(ALIAS) 모두 LIKE — UNION 또는 LEFT JOIN으로 중복 제거
- **담당자 ROLE**: primary는 한 명만(UK 검증), secondary/sales는 다수 가능
- **소프트 삭제**: ENABLED=0. 신규 SELECT는 ENABLED=1만
